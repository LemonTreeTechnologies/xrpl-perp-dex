# Участники кластера (`--member-peers`)

**Языки:** [English](member-peers.en.md) | Русский

Оркестратору можно указать, какие libp2p-узлы являются участниками кластера:

```
--member-peers <peer_id>,<peer_id>,<peer_id>
```

Каждый оператор перечисляет **всех** участников, включая собственный узел. Узел печатает свой peer id при
старте (`P2P started … peer_id=12D3Koo…`); id выводится из постоянного ключа идентичности
(`--p2p-key-path`) и не меняется между перезапусками.

## Что делает

- **Темы выборов и подписи:** сообщение принимается, только если и его подписанный автор, и узел, который
  его переслал, — участники.
- **Всегда, со списком и без:** сообщение выборов принимается только от того узла, от имени которого оно.
- **Темы реплицируемого журнала и протокол скачивания записей:** работают только с участниками; без
  списка транспорт журнала не запускается.
- Если список не задан или пуст, выборы и подпись остаются открытыми, как раньше, и в лог пишется
  предупреждение.

`--p2p-peers` не меняется: это только список адресов для подключения, а не правило доступа.

## Чего не делает

Список решает, кто может *говорить* в этих каналах. Он не решает, что сообщение может *сделать*: пакеты и
сертификаты принимаются только с подписями участников, проверенными внутри анклава по запечатанному
списку подписантов. Неверный список на одном узле влияет на связность этого узла, а не на полномочия
кластера.

## Режим реплицируемого журнала (`--log-store-dir`)

Когда анклав в режиме реплицируемого журнала, узел работает только при наличии всех трёх:
`--member-peers`, `--log-store-dir <каталог>` (постоянное хранилище журнала этого узла) и локального
подписанта из конфигурации подписантов.

- **При старте**, до подключения к соседям, оркестратор спрашивает анклав, включён ли режим журнала. Если
  режим включён и чего-то из трёх нет, оркестратор отказывается запускаться и называет, чего не хватает.
  Хранилище журнала без остального тоже отклоняется, и до генезиса (сборка анклава без журнала
  игнорирует эту настройку с предупреждением). Если ответ анклава прочитать
  нельзя, запуск повторяет попытки около двух минут и затем отказывается; он никогда не считает, что
  режим журнала выключен.
- **Если узел работает без журнала**, оркестратор продолжает проверять. Когда анклав входит в режим
  журнала, процесс останавливается (код выхода 78), и при следующем старте действует правило выше.
- Если заданы все три, узел следует журналу. `/v1/system/status` показывает это в разделе `log`: режим,
  позицию анклава и хранилища, `halted`, `diverged` и последние тревоги.

## Эксплуатация

- Добавить или убрать участника — значит обновить список на **каждом** узле и перезапустить каждый
  оркестратор.
- Некорректный peer id останавливает запуск (список никогда не укорачивается молча).
