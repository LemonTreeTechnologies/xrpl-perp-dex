# Разрешение на вывод v1 — контракт для клиента

*Английская версия: [withdrawal-authorization-v1.md](withdrawal-authorization-v1.md).*

Запрос на вывод несёт подпись самого счёта над ровно этим выводом. Каждый энклав, который
подписывает платёж с эскроу, заново собирает сообщение из платежа, который собирается подписать,
и сам проверяет эту подпись; без валидной подписи ни один энклав не подписывает.

## Поля запроса (`POST /v1/withdraw`, дополнительно к `user_id`, `amount`, `destination`, `destination_tag`)

| поле | тип | смысл |
|---|---|---|
| `user_pubkey` | hex-строка, 33 байта | публичный ключ счёта (`02`/`03`… secp256k1, `ED`… ed25519) — его XRPL-адрес должен быть `user_id` |
| `user_sig` | hex-строка | подпись дайджеста ниже: DER (secp256k1) или 64 байта (ed25519) |
| `auth_nonce` | **десятичная строка** u64 | ровно `last_withdraw_nonce + 1` (см. Номер) |
| `max_ledger` | целое (u32) | последний леджер, в который платёж может попасть |

Запрос без этих четырёх полей отклоняется с HTTP 400.

## Сообщение (106 байт, фиксированная раскладка, целые little-endian)

```
"PERP_WITHDRAW_AUTH_v1"          21 байт, ASCII, без терминатора
AccountID эскроу                 20 байт    (адрес эскроу кластера, декодированный)
AccountID пользователя           20 байт    (списываемый счёт = user_id, декодированный)
amount_drops                      8 байт    u64 LE — сумма в drops (1 XRP = 1 000 000)
AccountID получателя             20 байт
has_tag                           1 байт    0 или 1
tag                               4 байта   u32 LE (0, если has_tag = 0)
nonce                             8 байт    u64 LE
max_ledger                        4 байта   u32 LE
```

`digest = SHA-256(сообщение)`. Подписать `digest` ключом счёта. Принимается любая форма:
сам дайджест или `SHA-512Half(digest)` (так подписывают XRPL-кошельки, когда их просят
подписать 32-байтный хеш) — та же двойная форма, что у заголовков `X-XRPL-*`.

`amount` в запросе — тот же вывод в виде десятичной строки XRP, не больше 6 знаков после точки;
он должен точно равняться `amount_drops / 1 000 000`.

## Номер

Для каждого счёта строго по порядку: первый вывод — `1`, затем `2` и так далее. Текущее значение
— `last_withdraw_nonce` в ответе баланса (`GET /v1/account/balance`); отправлять ровно его `+ 1`.
Номер с пропуском или повтором отклоняется. По одному выводу за раз на счёт (последовательно на
стороне клиента). Вывод, который был принят и потом истёк без оплаты, номер израсходовал;
запрос, отклонённый до принятия, — нет.

## Срок

`max_ledger` — номер леджера. `LastLedgerSequence` платежа с эскроу никогда его не превышает,
поэтому платёж не может пройти позже. Берите текущий проверенный леджер плюс небольшое окно
(например, +60, около 3–4 минут). Разрешение со слишком близким `max_ledger` отклоняется
до каких-либо действий; подпишите новое.
